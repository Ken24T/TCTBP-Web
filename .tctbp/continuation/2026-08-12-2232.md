## Mistakes & Gotchas

1. **No false confidence (standing rule).** Never claim a fix works without verifying against the real files. This session proved it twice: (a) the ddre `release-build` gate fix was assumed applicable, then inspection showed ddre's `tctbp-run-gate.js` uses a hardcoded npm gate map and never reads `profile.commands` — no bug there, so the fix was withdrawn; (b) a preflight port for ddre was assumed surgically viable, then inspection showed 4 required modules missing and no root `package.json` (monorepo) — withdrawn. WHY: git stats and profile shapes imply, but only real files confirm, a fix's applicability. Always inspect the target file before claiming or applying a fix.
2. **Terminal corruption on complex inline `node -e`.** Complex inline `node -e` commands get corrupted input in this environment. Use temp script files for anything non-trivial, and delete them afterward. One such script (`.tmp-ddre-dep-check.js`) was accidentally swept into commit `4b4ba5f`; it was removed via additive commit `d610c30` — no history rewrite, per TCTBP rules. WHY: environment quirk, not operator error; the safety net was the additive-removal discipline.
3. **TCTBP safety rules.** No rebase/reset/stash/force-push; merges are ff-only; checkpoint is local-only and never pushes; publish pushes. All recovery must respect these (the stray-script removal used an additive commit precisely to avoid rewriting history).
4. **ddre is PRODUCTION on its own lineage.** Do no harm. It is schema 15, a different TCTBP lineage (monorepo, no root `package.json`). Leave it alone unless the operator gives an explicit, specific ask. The generic reconcile remains NO-GO; only the docs-only improvement was applied.
5. **Solo developer, no PRs.** The operator works directly on branches via `promote`; there is no PR review loop. Reconcile merges are performed directly on the consumer's working branch.
6. **Ship-time release notes.** At ship time in consumer repos, remind the operator to curate user-facing release notes (the automated notes are a starting point, not a substitute).
